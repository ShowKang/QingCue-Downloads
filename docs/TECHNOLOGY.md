# 工程难点与技术路线

本文以方向性叙述说明 QingCue 在工程上要解决的几类问题与整体思路。
不给出可复现的实现细节：不涉及算法步骤、计算公式、实现取值与内部命名。

## 1. 核心矛盾：识别不确定，阅读体验必须确定

流式语音识别输出的文本假设有三个特征：

- **不完整**：一句话在说完之前只能得到片段。
- **会修正**：后续音频可能导致前文被改写或吞并。
- **有抖动**：相邻两次输出之间可能出现增删。

如果直接把识别文本映射到稿件位置，界面就会随修正来回跳动。QingCue 的方向是**把不确定性关进对齐层**：

- 对外的进度是一根只允许前进或停留的轴。
- 中间结果用于**平滑**，稳定结果用于**定位**，两者职责分开。
- 新结果与已确认位置冲突时，以「已确认」为准；冲突信息只作为后续参考，不直接驱动画面。

这样，识别器的反复被消化在内部，渲染层拿到的始终是一个稳定位置。

## 2. 抖动与回退：识别修正不能变成画面回跳

识别器在后续音频到达时可能改写前文：同一个词被替换、被吞并，或整段文本被重新切分。
这些修正若直接作用于视觉位置，用户会看到高亮反复回退，阅读节奏被打断。方向是：

- 修正只影响尚未确认的部分。
- 已经呈现给用户的位置，不因后续修正而后退。
- 修正带来的偏差在后续朗读中逐步消化，而不是一次性跳转。

## 3. 从稀疏事件到连续运动：渲染与音频节拍对齐

识别是**事件式**的：说完一个词才可能输出一次结果；而人眼期待的是**连续**的高亮移动。
两者之间存在天然的颗粒度差。方向是在事件之间做**有约束的过渡**：

- 用最近的朗读进度估计当前节奏，画面按该节奏平滑移动。
- 长时间没有新证据时，画面会逐渐停止，而不是凭时间无限前进。
- 新的稳定结果到达时，以它为准校正，并让校正以视觉可接受的方式完成，而不是瞬移。

这带来一个必然取舍：**快读时的跟手性**与**慢读 / 停顿时的稳定性**无法同时最优。
系统选择偏稳定，代价是语速突变后的短时滞后。

## 4. 停顿、续读与跨句衔接

真实朗读不是匀速文本流：会停、会想、会重复、会改口，句子之间有长短不一的间隙。

- 停顿期间画面保持在当前位置，不以静默作为跳句依据。
- 恢复朗读后从当前位置继续推进，不需要重新定位。
- 跨句时在切换前完成后续内容的准备，使切换不产生额外等待；准备只影响流畅度，不改变推进判断。

## 5. 容错：朗读不会严格照着稿子

重复、回读、跳读、口误、插入语气词在真实场景中普遍存在。逐字精确匹配会让进度卡死。
QingCue 的思路是**以稿件为锚、以识别为证据**：

- 匹配以**句子**为天然边界，句子是容忍局部偏差的最小单元。
- 重复与回读表现为「停留在当前」，而不是退回前文。
- 跳读会被识别为进度前进；跨度过大时可能短暂停留再追上。
- 口误不要求逐字命中；连续、大范围的不一致时，系统倾向停在原位等待更多证据。

原则是：**宁可慢一拍，不可乱跳**。错误的推进比滞后的推进对演讲者伤害更大。

## 6. 低延迟与预热

从「开口」到「画面动」是一条串行链路：采集 → 识别 → 对齐 → 渲染。任何一层积压都会累积成可感知的延迟，
而且一旦产生就很难由下游追回。工程上的应对：

- 长时间连续运行不产生可累积的排队延迟。
- 识别持续输出中间结果，不必等一句话结束；对齐消费的是「流」，而不是「句」。
- 跨句成本在切换前摊销，让衔接不落在关键时刻。
- 渲染层只做增量更新，避免整块重绘造成的布局抖动与掉帧。

这条链路的难点不在于单层快，而在于**长稳**：连续朗读数十分钟时，不应出现隐性的内存增长或队列增长。

## 7. 本地离线与首次联网获取模型

本地运行意味着算力、内存、磁盘都由用户机器承担，不能假设服务器级资源。

- 识别在 **sherpa-onnx** 运行时上完成，模型选用 **Qwen3-ASR 0.6B INT8**：以 INT8 量化控制内存与算力占用，优先保证 CPU 可用性而非峰值精度。
- 模型与核心功能解耦：不使用语音跟随时不加载模型；首次启用需联网获取并校验完整性，之后可离线运行。
- 音频、文本、稿件全部留在本机；不存在「上传—返回」的网络往返，既降低延迟也消除隐私风险。

## 8. 视觉稳定：界面是跟随系统的「显示器」

渲染层承担两个容易互相冲突的目标：

- **准确**：高亮位置要反映真实朗读进度。
- **稳定**：画面不能抖、不能闪、不能突然跳行。

做法是把界面当作**一条单一时间轴**的投影：高亮、滚动、引导线都由同一个位置驱动，避免多个状态源各自为政；
更新只改变必要部分，减少重排与重绘。
滚动也做取舍：完全跟随会让快读时画面剧烈移动，完全固定又会让高亮跑出可读区。
系统选择**有界的视口跟随**——高亮接近可读区边缘时才滚动，并让滚动与高亮位移同源，避免两者互相追赶。

## 9. 桌面壳层与 Web 界面的边界

界面用本地 Web 视图表达排版与动效，窗口、输入、生命周期与持久化由原生壳负责。
这条边界的价值是**把系统集成的复杂度挡在业务之外**：

- 壳层保证单实例、置顶、快捷键与安装升级等平台行为。
- 视图层只处理呈现与交互，不感知设备与文件系统。
- 两侧通信保持**低频、批量、幂等**，避免高频消息引发的抖动。
